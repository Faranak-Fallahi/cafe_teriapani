# راه‌اندازی Supabase برای تریاپانی

## ساخت جداول و داده‌ی اولیه

1. یک پروژه در Supabase بسازید و از **SQL Editor** محتوای `schema.sql` را اجرا کنید.
2. سپس `seed.sql` را اجرا کنید تا ۹ دسته و ۲۸ محصول نمونه وارد شوند. تصاویر محصولات عمداً خالی هستند.
3. اگر داده‌های نمونه‌ی محلی را تغییر دادید، از ریشه‌ی پروژه `node scripts/generate-supabase-seed.mjs` را اجرا و seed را دوباره در پروژه‌ی Supabase اجرا کنید. درج seed از قبل موجودها را بازنویسی نمی‌کند.
4. URL پروژه و کلید **publishable/anon** را در `.env` محلی قرار دهید؛ از فایل `.env.example` الگو بگیرید. فایل `.env` در Git نادیده گرفته می‌شود. هرگز `service_role` را در اپ مرورگر قرار ندهید.
5. سرور Vite را پس از تغییر env دوباره اجرا کنید.

## ساخت حساب مدیر آزمایشی

در **Authentication → Users** یک کاربر آزمایشی با ایمیل و رمز دلخواه بسازید و UUID آن کاربر را بردارید. سپس در SQL Editor این دستور را با UUID همان کاربر اجرا کنید:

```sql
insert into public.user_roles (user_id, role)
values ('REPLACE_WITH_AUTH_USER_UUID', 'admin')
on conflict (user_id, role) do nothing;
```

رمز یا کاربر پیش‌فرض در مخزن قرار نمی‌گیرد؛ ساخت Auth user به اعتبار دسترسی پروژه نیاز دارد و SQL نباید رمز عمومی/ثابت بسازد. چند مدیر با ساخت چند Auth user و افزودن هر UUID به `user_roles` پشتیبانی می‌شوند. صفحه‌ی ورود این نسخه از ایمیل و رمز Supabase Auth استفاده می‌کند.

## امنیت و Storage

- `schema.sql`، RLS را روشن می‌کند: خواندن دسته‌ها/محصول‌ها/پیوندها برای ناشناس مجاز است؛ نوشتن فقط برای حساب دارای نقش `admin` مجاز است.
- همان SQL، bucket عمومی `product-images` را می‌سازد: نمایش تصویر عمومی است و بارگذاری/ویرایش/حذف فقط با نقش مدیر مجاز است.
- `is_admin()` به‌صورت تابع امن بررسی نقش مدیر را برای policyها فراهم می‌کند.

اگر env خالی باشد یا درخواست‌های خواندن به Supabase شکست بخورند، منو از mockهای فعلی استفاده می‌کند. در حالت mock ورود مدیر و نوشتن غیرفعال است؛ عملیات مدیریتی فقط پس از اتصال واقعی و اجرای schema فعال می‌شوند.
